Every finding opens to its evidence

Every command

Eight commands, one binary. Every command takes --help; analysis commands print text or --format json.

DepTrace commands, what they do, an example and their main options
Command What it does Example Main options
init Creates a starter deptrace.yml; --detect suggests layers from your folders and current imports. Never overwrites an existing one. deptrace init --detect --detect
scan Analyzes source dependencies and detects circular imports. deptrace scan ./my-app --format json --verbose
deps What a file imports, or which files import it. deptrace deps src/db.ts -d incoming -d, --direction -r, --root --format
path A shortest import path from one file to another. deptrace path src/index.ts src/db.ts -r, --root --format
check Evaluates the rules in deptrace.yml and prints a suggested fix for every violation; exit code 3 on violations. deptrace check --baseline deptrace-baseline.json --strict --baseline --format github --report --sarif --summary
report Layers, layer dependencies, rule results and cycles; always exits 0 when the analysis completes. deptrace report --format json --baseline --verbose --format
baseline Records today's violations so check --baseline fails only on new ones. create never overwrites; update replaces explicitly. deptrace baseline create create update --file
dashboard Explores the architecture in your browser, served on 127.0.0.1 only. deptrace dashboard --baseline deptrace-baseline.json --port --baseline --report
audit Known vulnerabilities in your installed npm packages, the files that import them, and the update that fixes each. The only command that uses the network: package names and versions go to the npm registry, never your code. deptrace audit --fail-on high --format --fail-on

Everywhere: -h, --help · -V, --version · --debug prints stack traces on failure.

Rules you write in one file

Name your layers with globs in deptrace.yml and choose the rules. deptrace check exits with code 3 when one is broken, so CI fails on the pull request that broke it.

Rule types
layer-boundaries Each layer imports only the layers you allow.
forbidden-imports Files matching one glob never import files matching another.
forbidden-packages Keep frameworks and Node.js APIs out of code that should not use them.
module-boundaries Feature modules meet only through their public files.
circular-dependencies No group of files imports itself, optionally ignoring type-only imports.

Built for CI

Commit a baseline of today's violations, and the check fails only on the ones a pull request adds. Here is that run on the sample project, line by line.

existing
Listed in deptrace-baseline.json, written once with deptrace baseline create. Still reported, never hidden, but accepted.
new
Not in the baseline: this import arrived with the change, so it fails the check.
1 resolved
An accepted violation that is gone. deptrace baseline update removes it so it cannot return unnoticed.
Exit code 3
The job fails on the pull request that broke the rule; 0 when nothing new fails.
CI integration
GitHub Actions Job summaries, annotations on the offending import, and SARIF for code scanning, from copyable workflows with pinned actions and read-only permissions.
Deterministic The same code gives the same report and the same fingerprints on every machine.
Fast enough for every push About 7 seconds for a synthetic 10,000-file repository on the benchmark machine (measurements).

Quick start

Four commands, in this order.

  1. 1

    Install

    npm install -g deptrace-cli

    Needs Node.js 22.12 or later.

  2. 2

    Write the rules

    deptrace init

    Creates deptrace.yml; add your layers and rules (rule guide).

  3. 3

    Check

    deptrace check

    Exit code 0 when the rules hold, 3 when they are broken.

  4. 4

    Explore

    deptrace dashboard

    Open the printed address; Ctrl+C stops it.

Your code stays on your machine

DepTrace parses files with the TypeScript compiler and never executes them. The dashboard talks only to its local server, and there is no telemetry and no account. The only network request is the dependency audit you run yourself: package names and versions to the npm registry, never your code.
